# P3.5b 渲染器定点回填 + Chocolate-Doom 逐帧比对骨架

- 日期：2026-07-26
- 分支：`feat/p3.5-fixed-point`（P3.5a 已落地，本阶段在其上继续）
- 上游 spec：`docs/superpowers/specs/2026-07-25-roadmap-realignment-design.md`（算法+数值双忠实）
- 前置已满足：vanilla 源码已取（`dbg/vanilla_r_{segs,plane,bsp,data}.c`，经 jsDelivr）；Clash 代理可用

## 1. 目标与范围

**数值忠实**：渲染核心从 float 改为 16.16 定点 + vanilla trig 表（`finecosine`/`finesine` 已有，新增 `finetangent`/`tantoangle`）。

**删桥**：删除 `main.cpp::bamToRendererRad`，`R_RenderView` 直接接收 `angle_t`。

**视觉忠实**：标杆机位与 chocolate-doom 逐帧比对，达到"视觉无差"（**非** bit-exact；容差见 §6）。

**附带修偏差**：用骨架量化并修掉本次会话发现的算法偏差（上墙条件反转、plane band 公式、贴图"分界线"），直到标杆机位通过。

**不在范围内**：坑底 HOM 黑带已由 `85fdc32`（下墙 bottomtexture 条件翻转）修复；精灵/敌人/音频/存档（P4+）。

## 3. 四阶段（测量驱动，方案 B）

每阶段都以 chocolate-doom 标杆帧为同一 oracle，偏差用数字衡量：

1. **搭骨架 + 锁机位**：装 chocolate-doom；为 E1M1 标杆机位录制/构造 demo（玩家起点为主，外加 2–3 个 demo 可达机位）；验证能在指定 tic 自动截 PNG（见 §5）。
2. **测基线**：用骨架测**当前 float 渲染器** vs vanilla 的偏差，落 `dbg/diff/baseline-*`；产出各偏差类的像素数字。
3. **定点回填**：执行 §2 的 float→定点 + 删桥 + 加表；重测偏差，须 **≈ 基线**（证明只换表示、行为未变）。若偏差显著变大，说明定点化暴露了被浮点精度掩盖的边界 bug，需 bisect。
4. **逐类修偏差**：按测量驱动一类一类修（§4），每修一类看偏差下降，直到标杆机位达 §6 容差。

## 4. 待修偏差清单（阶段 4 由测量确认；非穷举）

- **上墙（toptexture）条件反转**：`r_bsp.cpp` 现为 `cH_b > cH_f`（后天花板高时画），vanilla `r_segs.c:570` 为 `worldhigh < worldtop`（后天花板**低**时画）。须与 plane band 同步改，单独改会回归（已验证：pit 65→472、起点 1671→4528）。
- **plane band 公式**：高于视点的地板 / 低于视点的天花板，其 visplane 带算错（`[yFloorF+1, fc-1]` 对 above-eye 平面会越过地平线覆盖下方）。
- **贴图"分界线"**：sector/seg 边界的未覆盖像素（实测玩家起点 col 265/287 等为 `(0,0,0)` 散点），与上条同根因。
- **markCeil/markFloor 方向化**：现为 `>`/`<`，vanilla `r_segs.c:537,550` 为"高度不同"（`!=`）。须与上墙一起改。

## 5. 帧比对骨架

- **oracle**：`chocolate-doom -iwad assets/freedoom1.wad -playdemo <pose>.lmp -nosound -nosfx -nomusic -window`（或 `-fullscreen` 关闭）。demo 在固定 tic 触发 F1（截图动作）→ 确定性落 `doomXXXX.png`。
- **doomcpp 侧**：`--dumpframe <wad> <bmp> [angleDeg] [px py]`。玩家起点两引擎天然一致；demo 可达机位先用 chocolate-doom 回放该 demo，借 `idmypos`（控制台坐标显示）或 demo 解析工具读出目标 tic 的 (x,y,ang)，再喂给 `--dumpframe`。
- **标杆机位集**（至少 3 个）：① 玩家起点（E1M1 start，天然对齐）；②③ 两个 demo 可达机位（从起点直走/转弯到不同区域，覆盖天花板台阶与贴图缝场景）。
- **diff 脚本**（`tools/framediff/diff.py`）：将两边帧统一裁到 320×200；输出：结构差（异或轮廓像素数）、逐像素亮度差直方图、差分图 PNG 落 `dbg/diff/`。

## 6. 验收容差（"视觉无差"）

- **无大几何错位**：墙/开口/平面边界的屏幕位置偏差 >2px 的连通区域为 0（贴图 1px 对齐差异不记）。
- **无 HOM 类大块未覆盖**：未覆盖连通区域面积为 0（`--dumpframe` 洋红清屏扫描，沿用本次会话方法）。
- **逐像素**：>99% 像素 |Δ亮度| ≤ 12/255；剩余差异集中于贴图 1px 对齐与颜色表精度（vanilla 用 32 级 light table，doomcpp 现为连续 shade）。
- 全渲染/碰撞核心走定点；既有测试 **70/70 全绿**。
- `git grep "bamToRendererRad"` 无结果；`r_bsp.cpp`/`r_plane.cpp` 内除表生成外无 `float`/`double`/`std::sin` 等。
- 合并整个 P3.5（a+b）→ main，tag `v0.9`。

## 7. 风险与回退

- **chocolate-doom 帧捕获确定性**：阶段 1 先验证 demo+F1 截图能稳定复现同一帧。若不成，退化为"vanilla 源码逐数值对齐（投影/列高/跨度公式 vs `dbg/vanilla_r_*.c`）+ doomcpp 自身洋红 gap 扫描"作为 oracle，达标判据改为 §6 后两条（无 HOM + 定点化），放弃与 chocolate-doom 的逐像素比对。
- **定点化暴露隐藏 bug**：阶段 3 偏差若 > 基线即中招；用 `git` bisect 定位是哪个定点化步骤引入，单独修，不与 §4 的算法修复混在一起。
- **`tantoangle`/`finetangent` 表尺寸/索引**：严格对齐 vanilla `tables.h`/`r_local.h` 的常量（`FINEANGLES=8192`、`SLOPERANGE=2048` 等），避免越界。

## 8. 测试策略

- 定点化是行为保持重构：每个文件改完先跑既有 70/70；`r_bsp`/`r_plane` 无单测（项目约定：视觉验证），用 `--dumpframe` + 洋红扫描 + chocolate-doom diff 代替。
- 修偏差（§4）按"测量→改→复测"循环，每类一次提交。
- 关键数值（投影、列高、跨度距离）可加一个 `--trace` 诊断模式（沿用 P3.5a 诊断风格，临时可逆），dump 少量列的中间值与 vanilla 公式手算对齐。
