# 14 音频

## 不做这件事会怎样

砍掉音频不是"安静一点"。开枪没有上膛声，玩家会以为枪坏了；怪物在背后醒来没有咆哮，第 12 章整条"视线/噪音唤醒"链路就失去了唯一可感知的输出——AI 存在，但玩家永远不知道它存在。而反过来，音频代码写得马虎，代价更隐蔽：游戏线程直接写声卡，缓冲区满时主循环阻塞在音频驱动里，35 帧的逻辑节拍被一个异步设备拖成周期性卡顿，复现极难；CI 机器上没有声卡，游戏启动即崩，于是所有想跑真实主循环的 headless 测试跟着一起死。音频是引擎里少数"正确时无人注意、错误时全体遭殃"的子系统，值得按第 16 章的标准单独设计。

## 14.1 两个问题，不要写成一条代码路径

DOOM 的音频其实是两个不相干的问题：

| | 音效 | 音乐 |
|---|---|---|
| 本质 | 几十毫秒到几秒的短采样，最多八九个同时 | 一整首几分钟的乐曲，任何时刻只有一首 |
| 时间域 | 事件驱动：游戏逻辑喊一声就响 | 时间驱动：音符按乐谱时刻自己排 |
| 生命周期 | 一次播放，播完即忘 | 跨关卡存续，换曲目要淡出替换 |
| 数据 | DMX 采样 lump | MUS 或 SMF 乐谱 lump |

把它们塞进同一条代码路径是常见的架构错误：音效混音器被迫做流式缓冲，音乐播放器被迫每次 tick 查询"现在该响什么"。正确的切法是共享同一只"输出回调"，回调内部各自独立：音效侧遍历活动通道，音乐侧推进乐谱时钟，两者把样本累加进同一段缓冲。它们唯一该共享的就是这只回调。

## 14.2 音效管线：一张表、八个通道

音效系统的全部分支都挂在一行查找上：**id → lump 名 → 解码后的样本**。

```text
表:   sfx_names[id] = "PISTOL"          # 编译期常量表，与枚举同序
加载: 对每个 id，读 "DS" + name 的 lump，
      解 DMX 头 → 重采样到设备率 → 存入 sounds[id]
播放: I_StartSound(id, volume) → 找一个空闲通道，
      放入 (sounds[id], pos=0, step, volume)
混音: 回调每次取一批帧：
      for ch in channels:
          while 本批未读完:
              out[i] += pcm[ch.pos >> 16] * ch.volume / 127
              ch.pos += ch.step            # 16.16 定点步长
          样本播完 → 通道置空闲
```

通道数固定（原版 8 个，本实现也是 8 个）是刻意的：混音成本有硬上界，永远不可能因为玩家开了等离子加机枪外加三只男爵火球而卡住回调。通道全满时要抢——原版的 DMX 模型给每个通道记 (优先级, 音量, 来源)，新声要么挤掉"音量最低/优先级最低/最老"的通道，要么自己放弃；武器声优先级最高，环境声最先被牺牲。**本实现退化成了"抢第 0 号通道"**，这在一个 8 通道的规模上不常出错，但它是个已知占位，不是设计。

距离衰减同样值得一个表：DMX 用一张声压表把"到声源的距离"换算成音量台阶（原版是逐块的 attenuation 档位，不是连续函数）。加上声道定位，就得到廉价到可笑的"3D 音频"：

```text
bearing = angle_to(source) - view_angle     # 声源相对视线的方位角
separation = pan_table[bearing 的扇区]      # 0 = 正前，越大越偏一侧
left  = volume · (127 + separation) / 256
right = volume · (127 - separation) / 256
```

只要方位角和音量对了，玩家就能准确判断"左前方、隔着墙"——这套表驱动的定位在 1993 年成立，今天依然成立，因为它赌的是人对**双耳时差/响度差**的敏感，而不是任何声学建模。当前实现两者都还没做：单声道输出、音量只在调用点给一个常数。管线接口（`play(id, volume)`）留了位，补距离表和声像表不需要动混音器。

## 14.3 采样格式：DMX 头的脏活

DOOM 世系的音效 lump（前缀 DS）携带一个自定风格的头。文档里流传的"标准 DMX 头"是个家族：

| 偏移 | 字段 | 说明 |
|---|---|---|
| 0 | format | 0 = 8-bit 无符号 PCM；1 = 16-bit 有符号小端；Freedoom 用 3（仍是 8-bit 无符号） |
| 2 | rate | 采样率（常见 11025 / 22050） |
| 4..7 | channels / compression（原版）| 几乎总是 1 / 0 |
| 4..7 | 样本数（本仓库手上的文件）| Freedoom 的 DS lump 在这四个字节放的是总样本数 |
| 8.. | 样本数据 | 原版尾部还可能挂一张 60 字节的音量参考表，必须剥掉 |
| （Heretic 系扩展）| loop start / loop length | 循环点，DOOM 本体不读 |

这里的教训比格式本身重要：**头字段语义是民俗，手上的字节才是法律。**本实现的解码器读 format 和 rate，按 count 与"lump 大小 − 头长"取小者截断样本，两种采样宽度各自转换成 16-bit 有符号（8-bit 无符号减 128 再左移 8 位）。写错任何一步的代价都是可听的：不剥头 = 开头一声爆响；不减 128 = 整段音轨带着直流偏移嘶嘶作响；忘了尾部表 = 每个音效结尾多 60 个样本的杂音。这些 bug 没有任何测试会崩，只会"听起来不对"——所以它们必须被降级成数据问题：先 dump 前 16 个字节核对，再怀疑代码。

## 14.4 混音必须发生在回调线程

音频设备的模型是拉取式：驱动按固定节奏（比如每 1024 帧）调用你的回调，回调必须在下一个期限前交出一批样本。这决定了线程纪律：

- **游戏线程永远不写设备。**它能做的只是"投递请求"：登记一条"在哪个通道放哪个样本"。本实现用 SDL 的 `LockAudioDevice` 把通道数组的写侧包起来——请求函数拿到锁、填一个槽、放锁，锁的持有时间是微秒级；回调自身不拿锁，只读混音状态。换成无锁环形队列也完全可以（更纯），但纪律是同一个：**跨线程共享的只有通道槽位表，且游戏侧的写入必须在回调周期之外完成。**
- 反过来的写法——游戏线程直接调用设备写样本——会在缓冲区满时阻塞调用者。游戏主循环于是被音频驱动的节奏支配：卡顿、丢 tic、以及只在某些声卡驱动上复现的诡异现象。这类 bug 几乎不可调试，因为现场在另一个线程的时间轴上。
- 换曲目同理：解析可以留在游戏线程（慢工），但**替换"当前乐谱"这个动作必须原子**——本实现把整首曲目 move 进一个全局状态时用音频锁夹住，保证回调不会读到半新半旧的乐谱。

## 14.5 重采样：朴素的整数走步就够

采样率是资产属性（11025/22050），设备率是环境属性（常 48000），两者对不上就必须重采样。朴素做法已经足够：16.16 定点的 `pos` 每输出样本加一次 `step = src/dst` 的定点比值，取 `pcm[pos>>16]`，可加一个相邻样本的线性插值。22050→48000 的比值约 0.46，意味着平均每两个输出样本消耗不到一个输入样本——走步单调、无状态、无分配。为什么可以这么糙：音效样本极短、以瞬态为主，阶梯感被内容本身掩蔽；人对"音色略糙"远不如对"晚了 30 毫秒"敏感。本实现更进一步：加载时一次性线性重采样到设备率，回调里 step 恒为 1<<16，混音循环退化成纯加法——用一点内存换回调里最便宜的循环。只有在需要变调（原版没有）或低延迟合成时，才值得在回调里保留走步。

## 14.6 音乐：MUS 是给 OPL 写的，你的资产未必是 MUS

原版 DOOM 的 MUS 格式围绕一块声卡生长：头之后是事件流——增量时间、状态字节，音符起止编码成"通道 + 相对音高 + 音量 + patch 号"，另带控制列表，patch 号查一张 OPL 音色表（调制器/载波参数）。整套设计的终点是**直接喂给 OPL 芯片寄存器**。

但今天可自由分发的 IWAD（如 Freedoom）里，D_ 前缀的乐曲 lump 根本不是 MUS，而是 **Standard MIDI File（SMF）**。这个事实改变设计结论：资产是 SMF，你就该写一个"乐谱解析器 + 软件合成器"，而不是去仿真 OPL——OPL 仿真只有在资产真是 OPL patch 库时才是必需品。随之而来的是一个必须白纸黑字承认的取舍：**旋律、时长、节奏、换曲逻辑可以做到忠实（它们就在乐谱里）；音色不能（你没有当年那块芯片的乐器）。**我们的合成器是正弦加八度泛音、带快起音指数衰减的包络，E1M1 听起来"是它"，但没有人会把它认成 SB Pro。把这件事写进限制清单，比假装无损诚实得多。

## 14.7 最小 SMF 解析器需要哪些件

SMF 很大，DOOM 曲目用到的子集很小，按顺序六件事：

1. **MThd 头**：格式号、轨道数、division（每四分音符多少 tick；遇到 SMPTE 编码就退回 96 PPQ——本实现如此，并写明）。
2. **逐条 MTrk**：长度前缀的块，逐条解析。
3. **delta time 是 VLQ**：每字节 7 位有效、最高位表示续接，累加成绝对 tick。
4. **事件**：note on/off（**velocity=0 的 note on 等价于 note off**——乐句数据大量依赖这条别名）、program change（记录该通道当前乐器，写进音符的元数据）、running status（状态字节可省略，默认沿用上一个）。
5. **元事件**：0x51 set tempo（微秒/四分音符）是 tick→秒换算的全部依据；0x2F 轨道结束。
6. **循环**：DOOM 的关卡音乐从头循环——播到全长就复位时钟与游标，不找"无结尾"的尾奏。

解析产物是一个扁平化的音符表（起止秒、音高、力度、通道、乐器），按开始秒排序。混音回调里只需一个游标加一个活动音符集合：到点的音符入列表，过期的音符出列表，每帧把所有活动音符的正弦累加进缓冲。**tick 到秒的换算必须在解析期做完**，回调里没有乐谱概念，只有墙钟——这是"两个问题不共享代码路径"在音乐侧的对应物。

验证同样要 headless：把整首曲子离线合成进一段缓冲、算 RMS 能量（`--soundtest` 断言解析出的曲目数达标、坏曲为 0、D_E1M1 两秒合成的 RMS 大于阈值）——这是"音乐版本的离屏渲染"：不装声卡也能证明乐谱解析对了、合成器在发声。

## 14.8 没有声卡的路径也要是真路径

CI 和录制机器上常常根本没有音频设备。规则：**每一个音频入口都必须在"无设备"下退化成安全的 no-op**——初始化失败则播放直接返回、挂钩函数是空指针检查过的函数指针、核心逻辑（doomcore）从不链接 SDL，音效调用经由一个可替换的函数指针进入平台层（第 1 章的边界）。于是第 16 章那批跑真实主循环的 smoke 测试在任何机器上都跑同一条代码路径，音频最多"沉默"，绝不让游戏启动失败或测试挂起。注意一个细节：`--soundtest` 在无设备时选择**跳过并返回成功**，而不是失败——门要检验的是"音频路径坏没坏"，不是"这台机器有没有声卡"；把环境缺失报成代码失败，是制造假红灯。

## 这样做的代价 / 放弃了什么

- 音色忠实度整体放弃：没有 OPL（资产也不是为它写的），合成器是单声道正弦+八度，弦乐和金属没有区别；program 信息解析了但合成器没用上。
- 音效单声道、无距离衰减、无声像；通道抢占是"抢第 0 号"而非按优先级淘汰——同时超过 8 个声音时，最先登记的会被踩。
- 不做流式资产解码：所有 DS lump 启动时全量解码进内存（几十 kB 到几 MB 量级，换零运行时开销）。
- SMPTE 时间码、控制变化（弯音/延音）、SysEx 全部忽略——Freedoom 的关卡曲没有依赖它们，换一首依赖的资产就会"旋律对但表情平"。
- 采样格式只认 8-bit 无符号与 16-bit 有符号两种；原版尾部音量参考表被"按 min(count, 剩余长度) 截断"策略吸收，不再单独建模。

换取的东西：一条在有无声卡、有无外网、有无参考实现的任何环境下都能跑的路；一个成本有硬上界的混音器；以及"音乐坏了也只坏音乐"的隔离度。
