# 08 精灵渲染与遮挡

## 不做这件事会看到什么

把精灵画对只需要投影公式；让精灵**被挡对**则需要三次返工。第一种坏法：怪物永远正对着你转，绕到它侧面它还是那张正脸。第二种坏法更早就出现过：房间里一块 32 单位高的矮台阶，把整个房间所有怪物挡得干干净净——你站在台阶这头，那头的主力怪集体隐身。第三种最顽固：怪物站在抬高的平台**后面**，上半身被平台挡住、下半身却从平台顶面穿出来，一条腿悬在石头里。玩家未必说得清哪里怪，但一眼就能看出"穿模了"。这一章按这三次返工的顺序讲。

## 公告板与八方向旋转

精灵不是 3D 模型，是一组**面片（patch）**：每个朝向一张二维图，永远正面朝向相机（公告板）。地图物件（mobj，第 10 章）只记录 `sprname`（4 字母）、`frame`（1 字母，动画帧）和朝向角；一个 sprite 帧要么一张图打天下（`frame` 后数字为 0，比如装饰物），要么八张图对应八个朝向扇区（数字 1..8）。lump 名还能省一半资源：`TROOA2A8` 表示 A2 正面安装、A8 水平镜像复用——镜像安装省的是纹理内存，不省旋转逻辑。

选哪张图的公式只有一个相对角：从**玩家指向物件**的方位角，减去**物件自己的朝向角**。为零时玩家在它正后方，应取"背影"。原版把它量化成八份用的是定点右移，浮点等价写法是：

```
relAng = atan2(物件y − 眼y, 物件x − 眼x) − 物件朝向角
a      = wrap(relAng + 202.5°, 0..360°)          // 202.5° = (45°/2)·9
rotIdx = floor(a / 45°)  clamp 0..7
```

那个古怪的 202.5° 偏移是唯一需要解释的地方：把 0° 旋转（正后方）放进某个扇区后，**扇区的分界线**恰好落在玩家能绕圈看到的八个离散"正"方向上；202.5 = 180 + 22.5，等于把网格推移半个扇区，使"正后方"落在 4 号扇区的**中央**而不是边缘。少加或多加 22.5°，玩家绕怪行走时会在正后方原位突然左右甩脸。测试方法也直接：绕怪转一圈，换图的位置应当均匀分布在八个方向上、正后与正前各稳定在一个扇区中段。

## 投影与垂直锚点

把物件变换到相机基（与第 05 章同一个基：前向深度 + 横向），一列一个缩放：

```
depth = dx·sin + dy·cos;  lateral = dx·cos − dy·sin     // dx,dy = 物件 − 眼睛(平面分量)
if depth ≤ near: 丢弃
scale = 1/depth;  ppe = focal·scale                       // 每 texel 占的屏幕像素
x左 = 半宽 + focal·lateral·scale − leftoffset·ppe
x右 = x左 + 纹宽·ppe
```

垂直方向的关键不是把贴图中心钉在物件 z 上，而是**贴图的顶边对应哪个世界高度**：

```
gzt = 物件z + topoffset
屏幕行 y 对应贴图行 = floor(gzt − 反投影(y))     // 与第 06 章 V 同一下行约定
```

`topoffset` 是 patch 头里的"锚点距贴图顶的行数"（第 03 章）。它让一件东西不必重画就能正确挂：火把的贴图顶部留白到火焰，锚点记在白区下缘，于是同一个 z 值（ spawn 高度）让火焰出现在该出现的行；道具的 topoffset 约等于贴图高，锚在物件 z=地面时贴图顶恰好在底之上——**立在地上**。忘了 topoffset 的症状一眼可辨：所有东西吊在半空或陷进地里。

## 遮挡的第一次返工：每列深度是错的，两边都错

有了投影，只缺"该不该画这个像素"。最自然的答案是复用第 05 章的深度直觉：遍历墙时记一个每列数组 `columnDepth[x] = 这列最近的不透明墙深度`，画精灵时 `if (columnDepth[x] > sprite.depth) 画`。两个方向都坏：

- **过度遮挡**：一堵矮台阶离眼睛 32 单位，它的列深度 32 记录的却是**整列**。台阶只盖住下面几行，可上方半屏的怪物每一行都去跟 32 比——整房间怪物消失。这就是本文开头的第二种坏法。
- **遮挡不足（反方向）**：一列上近处的墙只盖住了部分行——masked 栅栏按规则不推进钳位、不写列深度，upper 墙只垂在视平线上方——于是这一列的"最近深度"来自远处那堵 500 单位的外墙；站在 100 处的怪物整身都通过，**连栅栏的实心柱子都盖**。列粒度只会回答"这列最近的不透明墙在哪"，表达不了"这列只有几行被挡住"。过度遮挡和遮挡不足是同一个病根的两张脸：每列一个标量，撑不起每像素一个真值的判定。

## 第二次返工：每像素深度

把数组升维成 `depth[y][x]`：第 06 章画墙 texel 的循环里，凡是写了不透明像素的地方，同时记录该列深度（取更小者）。判定变成逐像素：

```
if (depth[y][x] ≤ sprite.depth) 跳过这一个像素
```

矮台阶只污染它真实盖住的行，怪物上半身恢复。masked 墙只在非透明 texel 写深度，栅栏后面的东西继续透过洞显示。注意墙与精灵比较的**深度语义要一致**：两边都是"前向深度"（相机基的 depth 轴），不是欧氏距离——混用会得到斜面上半人半影的脏结果。

## 第三次返工：只有墙写深度是不够的

`depth[y][x]` 若只有墙写过，地板/天花板所在的像素全是 +inf。平台后面的怪物：平台**顶面**是 visplane（第 07 章），填充时没写深度，于是怪物下半身的像素畅通无阻地盖在平台顶上——本文开头最难看的那种穿模。修法只有一条：**平面填充循环同样写进这张每像素深度**。sky 例外，永远不写（天空在无穷远，写了等于把所有精灵藏进天空里）。

跟着是一个等号陷阱。怪物**站在**地板上：它脚底那一行视线打到的地板点几乎就是它的脚，平面深度与 `sprite.depth` 数学上相等、浮点上各方向都可能。若判据写成 `depth[y][x] < sprite.depth`（严格才挡），脚下的地板挡不住脚，脚部像素与地板花纹互相渗透、且随相机位置时好时坏。正确组合是：

- 判据保持 `≤`：等深的**墙**本来就该挡住贴墙的精灵（怪物鼻尖贴着墙，墙赢）；
- **平面写深度时加一点正向偏置**（半地图单位量级，`dist + 0.5`）：站在平面上的东西永远不被"自己踩着的这块地"挡住。

偏置加在写入方而不是把比较放宽，是这个 bug 唯一不引入新 bug 的修法——放宽比较会同时赦免所有贴墙精灵，症状从"脚消失"变成"贴墙怪物半截穿出墙"。

## 精灵之间：画家算法与它的坏账

世界画完（墙、平面），精灵才开始。每个精灵在 BSP 遍历经过它的 subsector 时只是**被收集**（投影 + 解析贴图帧），遍历结束后按深度**从远到近排序、依次覆盖**——公告板版的画家算法。两两分离的精灵排序后无懈可击；两个精灵**互相穿插**时（拥抱的怪物、堆叠的道具）排序在中心深度上只能分先后，后画的整幅盖前画的半幅，接缝处出现"一个怪物被另一个削了一半"的锯齿互穿。原版接受它，因为 DOOM 的怪物碰撞体让活物几乎不重叠；复刻时不要急着重造一个精灵级 z-buffer——先确认你的玩法允许穿插，再决定要不要付那个代价。

三件小事在同一循环里收尾：**spectre/fuzz**（`MF_SHADOW`）把贴图非透明像素与帧缓冲五五混合（原版的 fuzz colormap 是预计算抖动表，50/50 是它的可验证替身）；**fullbright** 帧灯光按 255 处理，不吃距离 shade 之外的环境光；**精灵灯光取它当前所在 sector 的 lightlevel，每帧刷新**——怪物从暗房走进亮厅那一帧就开始变亮，用出生时灯光的版本会在门口留一个"暗怪物"像没曝光过的底片。武器第一人称图层（psprite）不参与以上任何事：恒缩放、恒全亮、最后画、不做遮挡。

## 这样做的代价 / 放弃了什么

- **公告板没有真正的三维朝向**：俯仰不存在（怪在你脚下坑里仍直挺挺），大精灵近看分辨率随 `ppe` 涨到糊。这是 DOOM 的魔法而非缺陷，只是别指望它升级。
- **每像素深度缓冲 = 视图宽的每行一整个浮点数组**（320×168 约 210 KB）。原版用钳位数组省掉了它，代价就是上面三种穿模在原版同样存在。用哪头省，取决于你在意内存还是在意"怪物穿台阶"上玩家论坛的热度。
- **深度缓冲只记"最近不透明面"一层**：半透明叠半透明、精灵投影子进缓冲，这张单槽结构一概表达不了。想加，就得先回答"排序怎么和遍历顺序共存"——那是另一本书（延迟管线）的开篇。
- **画家算法接受互穿坏账**，每像素深度接受 0.5 单位偏置带来的"半单位内贴地精灵脚微浮"——两个都是明知故犯的近似，注释里写死，别让它长成"神秘 bug"。
