# 09 · 碰撞与移动

> blockmap 里的一次位置检查、三个高度变量、一条滑动规则——它们合起来解释了"穿墙"、"悬空"、"下台阶摔死"这三类 bug 为什么会产生，以及为什么被撞飞和走路必须走同一套代码。

## 不做这件事会怎样

先列症状，因为它们各自指向一个具体的省略：

- **穿墙。** 被火箭弹击中的一次击退，让人直接从墙里穿到墙后。不是碰撞"算错了"，是那一 tic 的位移比墙还厚，采样漏掉了整面墙。
- **下台阶悬空。** 玩家走下楼梯，脚还停在起跳地板的高度，视角飘在半空——因为 z 只在出生时算过一次。
- **怪物集体恐高。** 或者反过来：怪物从悬崖跳下追玩家，追得行云流水，但原版手感里它们明明会卡在台阶上——这是 `MF_DROPOFF` 标志丢失的症状。
- **贴墙走像被胶水粘住。** 朝斜 45° 的墙前进就彻底停住，而原版是顺墙溜走。
- **隐形桶。** 玩家绕开出生点以后，可以直接从油桶和怪物身上走过去——thing 间碰撞读到了一个幽灵般的高度。

这五条，每一条都由本章的一个机制负责。

## 玩家是一个 32×32 的方盒子，不是圆

碰撞形状是**中心在 (x, y)、半径 16、高 56 的轴对齐方盒**，它永远不随朝向旋转。

为什么原版用方盒：碰撞的核心判据是"盒子和一条线定义（linedef）是否相交"。方盒对它做四次叉积取符号就够了——纯整数、无开方、无三角函数，在定点时代这是决定性的。圆形对线的测试需要点到线段距离，里面必然有 sqrt 或它的近似。

代价在斜墙上：方盒的对角线比边长长 √2 倍，所以贴着 45° 斜墙掠过时，你感受到的墙比"看起来"宽；而且盒子不能斜着挤进 32 宽的缝——圆可以，方盒只有轴对齐时刚好能过。DOOM 关卡里那些"刚好过得去"的窄缝，全是按 32 这个直径设计的，这是形状选择和关卡设计互相锁死的例子。

## 一次位置检查：五道闸门

移动前先在区块图（blockmap）里取出盒子覆盖的所有格子（最多 2×2 个），对格内每条线（用代号去重，一条线会被相邻格子重复引用）依次跑五道闸门：

```text
P_CheckPosition(box, x, y):
    bbox   = [x-r, x+r] × [y-r, y+r]          # r = 16
    floorz = 起始扇区地板;  ceilingz = 起始扇区天花板;  dropoffz = floorz
    for 格子 in bbox 覆盖的 blockmap 单元:
      for L in 格内线条（本调用内去重）:
        ① bbox 早退:   L 的包围盒与 bbox 不相交 → continue
        ② 跨线判定:    bbox 四角在 L 同侧（叉积符号一致）→ continue
        ③ 单侧线:      L 没有背面 sidedef → 撞墙，报告阻挡线
        ④ ML_BLOCKING: 显式阻挡标志 → 撞墙
        ⑤ 两侧线:      求开口（opening）并折叠进三个高度：
             ceilingz = min(ceilingz, opening.top)      # 两侧天花板取低
             floorz   = max(floorz,   opening.bottom)   # 两侧地板取高
             dropoffz = min(dropoffz, opening.lowfloor) # 更低的边缘取低
```

第②道闸门是最容易被省掉、又最不能省的一条：**包围盒重叠不等于碰撞**。一条斜线的包围盒比线本身大得多，没有跨线判定，斜墙会膨胀成砖块状的一片假墙。

第⑤道是全部精髓：三个高度不是"查询"出来的，是把盒子碰到的**每一个开口折叠（max/min）进标量**。

## 三个高度各自防什么

| 变量 | 定义 | 为什么必须单独存在 |
|---|---|---|
| floorz | 盒子能站上的最高地板 = 所有跨过开口的 bottom 之最大 | 盒子同时压在台阶两侧时取高的一侧——这就是"跨在台阶上不掉落"的几何来源，也是抬高的平台/关闭的门变成阻挡物的原因 |
| ceilingz | 盖住盒子的最低天花板 = 所有开口 top 之最小 | 防止走进矮管道、防止在门还没开全时穿过门洞 |
| dropoffz | 真踩上去会跌到的最低边缘 = 所有开口 lowfloor 之最小 | 让单侧台阶成为"可以沿着走的墙"而不是悬崖：判定"往外掉会不会摔 too far"用它 |

没有 dropoffz 的实现里，怪物要么能跳下任何高度（失去台阶防守玩法），要么在任何台阶边缘畏缩（因为 floorz 无法区分"平地"和"悬崖沿"）。

## 接受检查

```text
P_TryMove(mo, nx, ny):
    pc = P_CheckPosition(box, nx, ny)
    if pc.blocked: return false
    if ceilingz - floorz < height: return false        # 站不下
    if ceilingz - mo.floorz < height: return false     # 从当前高度起身会顶穿
    if floorz - mo.floorz > 24: return false           # 上台阶超过 STEP_LIMIT
    if !(mo.flags & MF_DROPOFF) and floorz - dropoffz > 24:
        return false                                   # 会摔得太深
    接受；提交新位置，写入 floorz/ceilingz
```

玩家带 `MF_DROPOFF`，大多数怪物不带：24 单位的落差，玩家纵身跃下，怪物绕行。这不是偷懒，是刻意保留的玩法——高度是玩家可以滥用、怪物不会翻越的盾。

## 为什么每 tic 要切步：MAXMOVE=30

速度上限约 30 单位/tic，盒子宽 32——**单步位移必须小于碰撞体的检查窗口**。一次移动在物理层被切成若干 ≤30 的子步，每步独立跑上面的接受检查。

不切步会发生什么，正是"穿墙"的真实机制：当一次位移大于墙厚加盒宽，旧位置在墙左、新位置在墙右，**任何一次检查都从未让盒子跨过那条线**——五道闸门的第②步永远不触发。这是采样定理，不是碰撞精度问题。所以推论是硬的：**击退、爆炸抛飞、被男爵的火球掀飞的木桶，一切位移入口必须汇入同一个切步循环**。哪里写了"`mo.x += 击退距离`"这种直接加法，哪里就是穿墙 bug 的产房。

## 阻挡 ≠ 停下：滑动

撞墙后不把剩余动量扔掉，而是投影到阻挡线的方向上重试，最多三轮：

```text
P_SlideMove(d):
    for pass in 1..3:
        if P_TryMove(pos + d): return 成功
        d = (d · L̂) · L̂          # L̂ = 阻挡线单位向量，投影剩余动量
        if d 没有变短: break
```

没有它：朝 45° 墙按住前进键 = 死停。有它：贴着墙顺滑溜走。限定三轮是因为投影长度严格递减，三轮后动量已小到无感知；无限循环会在退化线上烧 CPU。抛射物被明确排除在外（第 10 章）。

## 动量、摩擦、推力——以及脚必须跟着地板

玩家的输入不是位移而是**推力**：每 tic 沿朝向加 forwardmove（走 25 / 跑 50 单位）到动量，动量先经 `MAXMOVE` 切步积分成位移，再乘摩擦系数（0xe800 ≈ 每 tic 衰减 9%）衰减，小于阈值直接归零。这带来"起步有加速度、松手有滑行"的手感；更重要的是击退共用同一个积分器——上面那条推论在代码结构上自动成立。

然后是本章最贵的一个教训，本仓库源码里它的注释比代码长：**对于不吃重力的 actor（玩家、走路怪物），z 必须由支撑面每 tic 重算**：`mo.z = mo.floorz`。如果 z 只在出生时写过一次，之后所有依赖高度的判定——thing 间碰撞的垂直区间、hitscan 的命中高度、精灵遮挡——读到的是出生地板的幻影位置。在 doomcpp 里它的症状是"离开出生层之后玩家能穿过油桶和怪物"，因为垂直重叠判定 `mo.z >= th.z + th.height` 里的 `mo.z` 是一个早已不成立的常数。视角高度、视线抖动（bob）再在 floorz 之上计算并对天花板做上限钳制。

## thing 与 thing

盒对盒，规则和线碰撞同构：水平方向 `|dx| < r1+r2 && |dy| < r1+r2`，再查垂直区间是否真的重叠：

```text
if mo.z >= th.z + th.height or mo.z + mo.height <= th.z:
    垂直让开 → 不阻挡
```

- 只带 `MF_SPECIAL` 的拾取物（pickup）与装饰不带 `MF_SOLID`，不阻挡。
- 死亡时引擎压缩 height（`>>= 2`），死亡链上的 `A_Fall` 清掉 `MF_SOLID`——**尸体不再挡路**，视线与弹道同时恢复通透。
- 诚实面对垂直测试的后果：站在怪物头顶正上方走下台阶的那一 tic，两个盒子合法重叠。玩家从怪物头上跳下去"穿过"它，这不是碰撞 bug，不要"收紧"成只看水平——那会造出玩家被自己的落脚点击退的怪事，还会让 24 单位台阶判定形同虚设。

## 这样做的代价 / 放弃了什么

- **方盒**放弃了斜向贴合的手感，窄缝判定永远带 √2 的别扭；换来的是无三角函数的跨线测试和与 blockmap 方格的天然同构。
- **轴对齐网格 + 每 tic 最多 30**是工程化的采样定理，不是连续碰撞检测（swept AABB）。任何绕过统一入口、单步超过盒宽的新特性（传送之外的瞬移、未来的高速武器）都必须自己负责切步，否则穿墙复活。
- **24 上台阶 + 无跳跃 + 无自由落体**把垂直能动性完全交给关卡（楼梯、升降台），换来的是玩家 z 恒等于 floorz 这条强不变式——第 08 章的精灵遮挡、第 12 章的近战判定都靠它才简单。
- **滑动限三轮**在极端楔形角落仍可能卡死，原版同款；再往上做"顶点圆角化"是手感增强，不是修 bug。
