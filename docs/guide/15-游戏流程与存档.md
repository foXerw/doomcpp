# 15 游戏流程与存档

## 不做这件事会怎样

没有流程层，引擎永远停在"单张地图的演示"：E1M8 尽头的开关按下去，世界安静如常；死亡之后没有重来，只有站在尸体视角的定格画面；F5 存了，F9 读回来的是黑屏，或者更糟——一个"看起来活着"但增益、弹药上限、机关进度全都丢失的半残状态。这些故障的共同特点是**不崩溃**：没有异常，没有错误码，只有"没发生"。它们是第 16 章里最难自动化捕捉的一类，所以本章除了讲怎么做，还要讲每一处"做错了会静默成什么样"。

## 15.1 游戏是一个小状态机，放在宿主层

整个流程需要的状态不多：

```text
enum GameState { Title, Playing, Intermission, Dead, Victory }

每帧（1/35 秒）：
  Playing:      跑逻辑 tic；玩家死亡 → Dead；出口触发 → 算下一关名 → Intermission
  Intermission: 画结算；按键 → 有下一关 ? 载入它并 Playing : Victory
  Dead:         按键 → 重载本关（不带库存）→ Playing
  Victory:      按键 → 从 E1M1 重新开始
  Title:        按键 → Playing
```

关键的架构决定是**这个状态机住在宿主层（唯一碰 SDL 的那层）**，而它调用的每个动作都是无 SDL 依赖的核心逻辑：`G_NextLevelName` 是纯函数，`P_SetupLevel` 不读输入，`G_SaveGame/G_LoadGame` 只碰文件。宿主层剩下的部分薄得可怜：读输入、判转移、调核心。收益立竿见影——流程可以整条 headless 自动化（`--campaigntest` 就是把这张状态机的每条边在无窗口模式下走了一遍），而如果反过来让核心逻辑去轮询键盘，流程测试就得雇一个假输入设备，多数人会偷懒不测。

## 15.2 关卡序列是数据，不是 if 链

DOOM 1 的关卡推进规则总共六条：M1–M7 进下一图；M8 进下一章节的 M1；E4M8 结束游戏；秘密出口进 M9；M9 打完**回 M4**（跳过秘密关之前的部分）；除此之外没有别的边。把它写成一个纯函数：

```text
next(cur, secretExit):
    (ep, map) = parse("E<ep>M<map>")
    if secretExit and map ∉ {8, 9}: return (ep, 9)
    if map == 9:                    return (ep, 4)
    if map == 8:                    return (ep+1, 1) ；ep==4 时返回 ""（通关）
    return (ep, map+1)
```

"下一关"的判定里出现不了散落在 UI 层的 `if (map == "E1M8")`——这就是全部意义：序列是一条数据性质的边表，任何一处需要它（结算页写 "ENTERING E1M2"、`--warp`、通关判定）都调用同一个函数。秘密分支、M9 回环、章节终点这些规则一旦有第二处副本，就会有第二处腐烂。

## 15.3 结算页：百分比的分母必须在战斗开始前存在

结算页三行数字：`killcount·100/totalKills`、`itemcount·100/totalItems`、`secretsFound·100/totalSecrets`。分子在事件现场累加（第 13 章：击杀记在死亡处，拾取记在消耗处，秘密记在首次踏入 special=9 扇区（sector）处，且每格只记一次）。分母的规则是本章最重要的一条：**总数必须在关卡装载、玩家还没开第一枪时统计完**——遍历出生清单，带"可计杀"标记的物件计数进 totalKills，"可拾取"标记的进 totalItems，扇区类型等于秘密的进 totalSecrets。

为什么只能这样：如果分母在统计时才算（比如"扫描一遍地图上的活怪物"），玩家一种怪没杀时，"杀光了全部 12 只"是 12/12，而"整关遇到的怪加起来才 0 只可杀"是 0/0——两种"零击杀"在数字上无法区分，而它们的含义恰恰相反。总数先于玩家行为存在，百分比才是对**地图**的陈述，不是对玩家操作的二次加工。除零的兜底取 0%（一张没有秘密的地图显示 0/0 时，0% 比 100% 诚实）。

## 15.4 跨关携带：actor 推倒重来，行李原样搬走

过完结算页，`P_SetupLevel(世界, 新地图, carry)` 做两件事，而且必须分开：

- **玩家这个"物件"重建**：从新地图的出生点 thing 重新 spawn——位置、角度、所在扇区、`floorz/ceilingz`、视角高度全部来自新地图的几何。旧 actor 的一切（包括它死过一次的尸体状态、卡在墙里的坐标）不带入。
- **玩家的"行李"复制**：血量、两个护甲池与生效类型、四类弹药**及其上限**、武器持有位图、当前枪、钥匙、以及增益数组 `powers[]`。计数器（killcount/itemcount/secretsFound）不在行李里——每个关卡从零开始。

两类事故就藏在这两行清单里。其一，**漏字段**：P8c 阶段的携带清单没带 `powers[]`——无敌、护身、狂乱在每一道出口无声蒸发，且因为没有测试覆盖"过一关"这件事本身，它活了一次完整版本周期。其二，**顺序错**：同一次改动在 clamp 弹药之前就把 maxammo 重置回基础值，背包装配过的玩家每次过关，超过旧上限的弹药被截掉——上限翻倍的意义随字段一起丢了。所以规则要写成制度而不是一次补丁：

> **携带清单必须与存档清单派生自同一个结构，或者被一个对照测试钉住。**两者描述的是同一件事——"玩家身上哪些字节是跨时间/跨地图持久的"。手写两份、允许漂移，就等于宣布每个新字段都要踩一次坑。最省事的钉法：写一个 roundtrip 测试——存档→读档的状态与"过一关 carry"后的状态逐字段相等。

## 15.5 存档：一个有版本号的二进制布局

存档不是快照整个进程，是快照**可变世界状态**。写盘的顺序本身是设计：

| 段 | 内容 | 为什么在这 |
|---|---|---|
| 头 | MAGIC("DCPS")、VERSION、地图名、tic、三个总数 | 先自检，再定语义 |
| 扇区 | 每格地板/天花板高度 + 秘密已发现位 | 门/电梯可能停在中间；地图静态数据不存，只存被改动的层 |
| movers | 每个机关的 kind/sector/上下限/速度/等待/方向 | 半开的门必须继续走 |
| 玩家标量 | health、viewz、护甲池×2+类型、ammo+maxammo、武器位图、当前枪、钥匙、计数器、dead、受伤抖动 | |
| psprites | 槽位状态索引 + tics + sx/sy | 枪可以停在收动画的中段 |
| mobjs | 数量 + 逐个：类型索引/xyz/动量/角度/高度/血量/flags/tics/状态/反应时间/**target 索引**/floorz/ceilingz/光照 | |
| **尾部新增** | `powers[]`（v3 新字段） | 见下 |

三条纪律撑起这个布局：

1. **交叉引用存索引，不存指针。**怪物的 `target` 指向另一个 mobj，指针值在下次进程里毫无意义；mobj 按链表顺序写出，target 写它在数组里的下标，读档重建列表后再按下标回链。任何"对象之间互相指"的新字段都照此办理。
2. **新字段一律追加到记录末尾。**v3 在末尾加了 `powers[]`：新读者读旧文件，读到尾巴发现没了，把增益置零继续跑——"尾部截断"解释为**该功能当时不存在**，而不是文件损坏；旧读者读新文件，读完它认识的字段自然停下，多余字节无人认领。字节对齐从头到尾只发生一次（改字段语义时升版本号，而不是就地改含义）。这就是为什么第一次用户的旧存档加载失败会是最贵的一次事故——规则现在不值钱，破例之后收不回来。
3. **读取要求同一张地图。**存档只是"某张地图静态数据之上的差量"：扇区高度表必须对得上扇区数，mobj 坐标必须落在真实的门和抬升里。所以载入流程是先比对地图名，必要时先加载**存档里那张地图**，再覆写差量。做"跨地图通用存档"要么存下整个地图（那不是存档是重放），要么维护一堆"这个坐标在新地图上意味着什么"的重映射——那是另一本书的难度，诚实地拒绝它。

## 15.6 死亡与重开：重开的是关卡，不是库存

玩家死亡后，状态机进入 Dead；按键后调用的是 `P_SetupLevel(本图, carry = 空)`——出生点重置、血量 100、手枪加 50 发子弹、行李全部从零，也就是原版的语义：**重开这一关是一次全新的开局，不是恢复你上一次的好状态**。这不是省事，是两套完全不同的设计：carry 为空意味着死亡会把"背包翻倍"这类地图获得物一并收回，而"复活保留库存"会让死亡惩罚塌缩成一次读盘等待。快速存档（F5）与死亡重开互不干涉：死人的存档不存在，因为写盘只发生在活着的时候。

## 这样做的代价 / 放弃了什么

- 存档绑定地图：换图即拒载，没有"在任何关卡落地"的旅行式存档，也不保存随机数状态——读档后的 RNG 序列是新的一段（对单人足够，对确定性重放/演示 demo 不够）。
- 只有一个快速槽（固定文件名），无菜单、无时间戳、无多槽轮转——全部是宿主层 UI 的欠账，不影响格式。
- 地图静态数据（linedef/扇区初始高度/物件表）不进存档，靠"先加载同名地图"保证一致：这是同一枚硬币的两面——省了空间，代价是永远不能承诺跨版本兼容（改了地图数据的 IWAD 会让所有旧存档作废，且应当作废）。
- 流程状态机写死为单人一命制：没有合作模式的 spectator/respawn 状态，没有技能等级分支。

买到的是：一条能被 `--campaigntest` 无头跑完的 E1M1→E4M8 完整通路、一种"旧存档加载失败会被当作缺字段继续跑而不是当作损坏"的兼容策略，以及一条在每次加字段时自动发力的纪律——携带清单与存档清单，要么同源，要么对质。
