# 07 Visplane 与地板天花板

## 不做这件事会看到什么

地板和天花板如果照搬墙的每-seg 画法，会得到两种坏画面之一：每个 seg 都把前 sector 的整片地板画满屏幕，重叠处纹理打架、亮度乱闪；或者更保守一点，只画"开口以下"的地板——于是相邻两个同高同贴图的 sector 之间出现一条横向接缝，地板花纹在缝上错位。还有一种更隐蔽的坏法：走廊中间本该是台阶的地方出现一整块纯色"黑石板"，像一堵隐形的墙横在视野里。本章讲 visplane 怎么解决前两种，并把第三种（本章的核心规则：**按开口收边**）讲到能验收的程度。

## 平面为什么不能跟着墙一起画

墙是**有界**几何：一条 seg 一段、高度区间确定，画过就走。地板/天花板是**无界水平面**：一块 sector 的地板在世界里没有边界，它在屏幕上"可见的部分"等于全屏幕减掉所有墙和其他平面之后剩下的窟窿。窟窿要等遍历结束才知道，所以原版把平面拆成两阶段：

1. **标记阶段**（嵌在 BSP 遍历里）：每个 seg 顺手宣布"第 x0..x1 列上，我的前 sector 的天花板/地板负责某一段行区间"，写进一张每列的带表。
2. **填充阶段**（遍历结束后）：对每张被标记的平面，把带表枚举成一条条水平跨度，逐行铺纹理。

标记时**必须跳过已经有不透明墙的行**——这正是两块钳位的另一个用途：在画墙之前读到的 `ceilingClip/floorClip` 就是"这一列上面/下面还有多少开放窗口"。

## visplane：按 (高度, 贴图, 灯光, 是否天空) 归并

```
struct Visplane:
    key   = (height, flat, lightlevel, sky?)     // 天空忽略 height/light
    minx, maxx                                   // 被声明过的列范围
    top[w], bottom[w]                            // 每列负责的行带；初值"未声明"
```

同一帧里，key 相同的区域归并成**一张** visplane。归并的收益不是省内存：40 个同高同贴图的 sector 相连成一片大厅时，每张 seg 都往同一个 `top/bottom` 数组里续带，填充阶段扫出来的是拼好的一整片跨度列表，而不是 40 份互相重叠的"各自视角里的大厅地板"——后者不仅要画 40 遍，而且 40 遍之间纹理坐标虽然一致、跨度却彼此覆盖，浪费全花在重复采样上。归并还有个容易被忽略的前提：**同 key 的平面彼此绝不相交**（每列每行只会被一个平面带声明一次，见下面的冲突分裂），所以填充顺序无关紧要， painter 式覆盖也不发生。

`R_CheckPlane` 处理唯一的例外：同一 key 的两段列范围如果在重叠列上都要声明行带（典型场景：两块同高地板之间夹着一条同 key 的中间区域已经被别人占行），带表会写冲突。原版的做法是**再开一张同 key 的平面**认领新的列范围——归并只归并"能安全归并"的部分。

**平面上限**：原版的 visplane 池是固定大小（每类 128 张），画满直接 fatal 报错。现代复刻可以改成动态增长，但要明白原版为什么封顶：一张平面 = 两根每列整数数组，而平面数量由**地图数据**决定。用户地图可以故意摆出成百上千个"同高度但贴图/灯光两两不同"的 sector，每多一张归并失败的平面就是一笔运行时才暴露的线性开销。固定池把这种地图变成**启动即报错**；动态池把它变成帧率悬崖或内存悬崖。选了动态，就把"这一帧建了多少张平面"变成可观测指标，否则你只是把崩溃换了个名字。

## 每行一个距离：yslope 与 distscale

平面铺纹理的核心问题：屏幕像素 `(x, y)` 对应平面上的哪个世界点？答案藏在视平线的相似三角形里。对第 `y` 行，视线与水平面的夹角由 `|y − centery|` 决定，平面离眼的高度差是 `|平面高 − eyeZ|`，于是该行到交点的**前向距离**：

```
dist(y)  = |平面高 − eyeZ| · yslope[y]        其中 yslope[y] = focal / |y − centery|
world(x) = 沿该视线在距离 dist 处的点          （distscale[x] = (x − 半宽)/focal 给出横向比例）
```

逐行只需一次除法级别的量（`yslope` 每帧按行建表），逐列则完全退化为**步进加法**：把跨度起点 `world(x1)` 算出来，之后每列加上 `dist/focal` 个单位在世界 x/y 上的投影增量，取整数部分 mod 64 就是 flat 纹理坐标（64×64 flat、1 单位 1 texel，第 03 章）。这正是第 02 章说的"用查表和步进把除法挤出内循环"的样板。

**地平线特例**：`y == centery` 时 `yslope` 的分母为零。两种"顺手"的写法都会翻车：直接除零得到 inf，后续判 `!isfinite(dist)` 跳过——每个户外视图的正中央从此躺一条一像素黑线；把它当 0 处理则该行被涂成眼前景深 0 的怪异纹理。正确做法是**给一个有限但巨大的值**（比如 `focal·64`）：这一行本来对应"无穷远处的地面"，距离 shade 自然压到最暗，行被正常画掉，黑线消失。教训：数值上退化的行也要有像素归宿。

跨度枚举本身是纯二维扫描：按行从 0 扫到底，在每行找出所有"该行落在 `top[x]..bottom[x]` 内"的连续列段 `(y, x1, x2)`，逐段调填充。同平面的多条跨度按 painter 顺序无所谓——同 key 不交叠，见上。

## 天空：永不按高度归并，填到地平线

天空 sector 的天花板通常挂在 512、1000 甚至更高的"名义高度"上。两个由此而来的特判：

- **归并 key 里忽略高度与灯光**：所有天空是一张平面（原版用同一个 `skyflatnum` 达到同样效果）。否则"名义天花板 512 的户外区"和"1000 的户外区"会各建一张天空平面，而在玩家眼里它们是同一片天。
- **天空行带向下填到该行对应的地板边缘（地平线方向），而不是名义天花板投影行**。若按名义高度收边，`y = 投影(1000)` 常常在屏幕外上方，天空只覆盖到"投影行"为止的话，天空与地面之间留下一条谁的管辖区都不到的黑带——户外场景底部横一条深色地平线缝。天空在无穷远，它合法地一直铺到视平线；地板接手之后剩下的才是地板的事。

SKY1 全景按**视角**映射而不是按列号：像素 `x` 的视线方位角 = 相机 yaw + `atan((x − 半宽)/focal)`，除以 2π 取纹宽列。这样转头时天空平移、视野中央正对谁一目了然；用列号直接映射的版本"转头天空不动"，一眼假。原版还有个每 tic 一列的缓慢 scroll，复刻时顺手做进纹理列偏移即可。

## 核心规则：平面按开口收边

第 05 章说过，每列每行的归属要在遍历当下一次定死。对双面线，前 sector 的平面带"该画到哪一行"取决于一个看似显然、错法无数的选择：用**前 sector 的名义高度**，还是用**开口**（两侧天花板取小、两侧地板取大，第 00 章术语表）？

规则（可背下来）：

```
openTop = min(前天花板, 后天花板)；  openBot = max(前地板, 后地板)
// 哪一侧的台阶面有贴图，哪一侧就用名义高度；没贴图的那一侧，用开口：
天花板带的下沿 = 有 upper 贴图 ? 投影(前天花板) : 投影(openTop)
地板带的上沿   = 有 lower 贴图 ? 投影(前地板)   : 投影(openBot)
```

**它修的是什么**：台阶面（upper/lower 墙）只有带贴图时才会被第 06 章画出来。地图里大量存在不带贴图的台阶——抬高的平台、关到位的门（门的中段贴图撤掉或本来就没有）、普通的高低差。此时台阶所在的行区间**没有任何墙负责**。若前地板平面按名义高度收边，它只铺到"前地板"对应的行；台阶区间落在两个管辖圈的缝隙里——上面的后 sector 平面管不到这侧，下面的前平面又不肯多铺——于是玩家看到走廊中间立着一整块纯黑石板，宽度恰好等于那堵隐形台阶。这就是"按开口收边"的字面含义：**没有台阶面贴图的地方，让平面多铺一段，把台阶的位置盖掉**——反正那是一个数学上的水平面，用哪块 flat 盖都"对"。

**为什么有贴图时必须回到名义高度**：平面填充发生在所有墙之后（标记/填充两阶段决定的）。台阶有贴图时，那段行区间属于墙的艺术；若平面也按开口伸进去，后画的平面把刚铺好的台阶纹理整个抹掉，贴图消失。所以判据是逐方向的"这一步的台阶面是否会被画"，各管各的上沿/下沿。

顺带两条例外，都是"画了也白画"的裁剪：单面线两侧同属一个视野遮挡，天花板/地板带都标；高度差为 0 且贴图灯光也无差别的双面线可以整段跳过标记（原版只在高度/贴图/灯光任一不同时标对应侧）；前地板高于眼且非天空、或前天花板低于眼且非天空时跳过——那一侧的行带在屏幕上必然是空的，标了也是白标（**注意天空不适用**：天空永远要标，见上面地平线一节，这个反向遗漏同样是黑缝的经典来源）。

**可证伪的验收**：这个规则的正确性无法靠肉点抽查——坏缝是 1 像素、坏在个别角度。可行的机器检查是把"没画到"变成计数：把每个 IWAD 地图的每关，在几十个位姿（含贴着墙角、正对台阶、门开合前后）渲染到**哨兵色帧缓冲**（清屏色取一种现实中不可能出现的亮品红），统计既没被任何墙写过、也没被任何平面带覆盖的像素数。**这个数必须为零**，非零的每一个位姿都直接定位到列与行，可回放进调试器。doomcpp 里这一步是 `--gapscan/--renderaudit` 工具族；没有现成工具时，"墙和平面各自写过一个覆盖位图，帧末数两个位图都为零的像素"三十行就能拼出来。第 16 章会把这类"负空间断言"归入方法论。

## 这样做的代价 / 放弃了什么

- **平面只能是水平面。** 无界 + 每行一条跨度的模型没有给斜面留位置；斜坡地板在 DOOM 语义里是用很多小 sector 阶梯化模拟的，代价由地图作者付。
- **两阶段结构把所有决定权交给了标记时刻。** 填充阶段没有任何遮挡知识，收边一旦错标，坏结果必然出现且只在特定位姿出现——这正是验收工具必须穷举位姿而不是抽样的原因。
- **归并假设同 key 互不相交，天空打破了"按高度归并"的直觉。** 保留原版式特判（sky 单独 key）比发明更聪明的归并条件划算：前者的边界情况已经被三十年的地图数据踩过。
- **开口收边让平面"盖掉"了本该是台阶的地方。** 如果地图作者想要一个不贴图的台阶但保留视觉上的厚度暗示（原版也给不了），这套规则下它必然被邻近平面的花纹抹平。这是约定，不是损失——只是要写进地图编辑器的文档里。
