# 06 墙渲染与纹理映射

## 不做这件事会看到什么

墙是全屏幕最容易"差不多就行"的部分，也是原版 bug 报告里最常见的三种画面都出自这里：控制面板贴图的**上下镜像**（按钮排到顶上去）；贴着一面长墙行走时，墙皮**沿着墙滑动**；台阶面与地板交界处一条**时隐时现的一像素缝**。三者分别对应本章的三个主题：V 的符号、U 的透视正确性、行取整约定。

## 一对正反投影，全章都在让它们自洽

一堵墙在屏幕上是**一列一列的垂直区间**（第 05 章的两块钳位决定区间开在哪）。每列只需要三个量：该列的深度 `depth`（相机前向距离）、由它导出的 `scale = 1/depth`、以及在这段区间里逐行采样贴图。世界高度 `z` 与屏幕行 `y` 的换算是一对互逆公式：

```
投影:   y = centery − focal · (z − eyeZ) · scale        // 世界高度 -> 屏幕行
反投影: z = eyeZ + (centery − y) / (focal · scale)      // 屏幕行 -> 世界高度
```

`centery` 是视平线行（视图高的中点），`focal = 半宽`（90° 水平视场）。注意 `scale` 对**整列**是常数——DOOM 的墙是垂直面，深度只随列变化不随行变化，这是后面一切能按列组织的前提。`z = eyeZ` 时 `y = centery`：视平线就是眼睛高度的世界平面，这个不动点是第 07 章地平线讨论的伏笔。

画一列的骨架：

```
syTop = 投影(zTop);  syBot = 投影(zBot)          // zTop > zBot，屏幕行 syTop < syBot
yA = max(ceil(syTop), ceilingClip[x] + 1)
yB = min(floor(syBot), floorClip[x] − 1)
for y in yA..yB:
    z = 反投影(y)
    V = anchorZ − z + rowoffset                  // 见"pegging"一节
    画 texel( U mod 纹宽, V mod 纹高 )            // U 整列不变
```

## U：透视正确不是修饰词

一列一个 U，听起来最省事的算法是：在 `[x0, x1]` 两端算出 `t`，然后逐列线性插值。**这是错的**，而且是长近墙上肉眼可见的错：屏幕列与世界距离的关系是双曲的（`t ∝ 1/depth` 的变体），线性插值等于假设"每列走过的世界距离相同"。于是一面从脚前 8 格拉到 200 格外的长墙，近处每列实际该跨好几个 texel、远处每列只有零点几个，插值把两头抹平——玩家平行于墙移动时贴图明显**漂移**，近端滑得飞快。

正确的做法在第 05 章已经铺好：每列做**视线与线段所在直线的求交**，得到交点参数 `t ∈ [0,1]`，然后

```
U = seg起点偏移 + sidedef纹理偏移 + t · seg世界长
```

`t · seg世界长` 就是交点到 seg 起点的**世界距离**，而约定是 1 地图单位 = 1 texel（第 02 章的单位制在纹理上的落点），所以世界距离直接就是 texel 数。拿数字掂一下量级：一面 8 单位到 200 单位的墙横跨大半屏幕，近端一列可能要走 3 个 texel，远端一列只走 0.05 个——相差六十倍。线性插值把这个比值强行摊平，纹理在两端错位、中段正确，玩家移动时错位量随透视变化，看起来就是贴图在"爬"。而逐列求交的版本里透视缩短被天然吸收：近处的列自动分到更大的 `Δt`。整张图里没有任何跨列插值，每一列的 U 都是从几何推出来的——这就是"透视正确的 U"在 DOOM 语境里的全部含义。宽度方向则纯靠取模：`U mod 纹宽`，一面 64 texel 宽的贴图在 300 单位长的墙上自动平铺四次半；`textureoffset` 为负也照常工作，只要你的取模修正了负数。

## V 与 pegging：三种锚，一个符号陷阱

贴图在墙上不总是从天花板顶开始铺。控制贴图对齐的是两个东西：sidedef 的 `rowoffset`（沿墙竖向平移）和 linedef 的 pegging 标志。对每种墙面，纹理 V=0 所在的**世界高度**（锚）如下：

| 墙面类型 | 出现条件 | 默认（贴图顶锚在…） | 带 DONTPEG 标志时（锚在…） |
|---|---|---|---|
| 单面 middle | 总存在 | 前 sector 天花板 | DONTPEGBOTTOM：前地板 + 纹高（贴图底贴地） |
| upper（天花板台阶） | 双面且 后天花板 < 前天花板 | 后天花板 + 纹高（贴图底贴后天花板） | DONTPEGTOP：前天花板（贴图顶贴前天花板） |
| lower（地板台阶） | 双面且 后地板 > 前地板 | 后地板（贴图顶贴后地板） | DONTPEGBOTTOM：前天花板（贴图顶贴前天花板） |
| masked middle | 双面且 后开口非空 | 前天花板 | DONTPEGBOTTOM：前地板 + 纹高（与单面同一规则） |

表里的"出现条件"值得单独盯一眼，因为它的方向错了不会报错，只会漏画。upper 面存在的条件是**后天花板低于前天花板**：台阶面属于前 sector，从它自己的天花板向下垂到对面较矮的天花板为止；写成反向（后高于前才画），真正的台阶一处都画不出来，倒是在别处提交一堆 `zTop < zBot` 的空区间、被钳位无声吞掉——症状是天花板台阶集体"没有立面"。lower 面对称：**后地板高于前地板**，即站在低处看抬高的平台的立面。这个条件本章的示例实现曾写反过，症状非常迷惑：坑沿的立面无缘无故消失、地图里到处出现"地平线悬空"的 HOM（hall of mirror），而截图里大部分场景完全正常——因为常见的台阶恰好都是"往上走"的方向，唯独掉坑视角全坏。记住判据的办法不是背方向，而是问一句：**这块立面是前 sector 的哪一层皮、朝哪边垂**。

DONTPEG 的语义值得多说一句：它把锚从"贴着某个可变的邻居高度"改成"贴着另一个面"，本质上是为了让**电梯门、力场**这类贴图高度钉死，不随对面 sector 的移动上下拉伸。默认 pegging 则相反——贴图跟着台阶走，接缝处永远对齐。

符号陷阱：V 必须**从锚向下增长**。屏幕行 `y` 向下、世界高度 `z` 也单调向下，所以 `V = anchorZ − z + rowoffset`。写成 `V = z − anchorZ + rowoffset` 的镜像错误极其阴险：对左右上下都近似对称的贴图（石砖），截图完全看不出问题；对 masked 贴图是灾难——透明行本来在贴图底部，镜像后跑到顶部，铁栅栏变成"上实下空"的鬼墙，而你在测试图上第一次看到它时它往往是"对的"（一张恰好上下对称的测试贴图）。判据必须用**不对称**的贴图。

取模要处理负数：`rowoffset` 和 textureoffset 都可以是负的，`V mod 纹高` 在语言层面对负数的定义未必是你想要的（doomcpp 里显式 `if (vi < 0) vi += height`）。

## masked middle：逐 texel 的洞

masked 贴图（栅栏、窗户、半墙）画在前后 sector 都开放的中段区间上，逐 texel 检查 alpha：透明则跳过。关键在于它**不推进两块钳位**（第 05 章）——BSP 序里后面的更远几何体会照常画进来，洞就是洞。它也不写这一列的"不透明记录"，所以第 08 章的每像素深度里，只有非透明 texel 才留痕。一个常见的设计疑问是"要不要画到开口外"：不画。masked middle 的垂直范围就是它的几何范围（挂在那里的一块贴图），上下露出的是别人的平面或墙。

## 行取整约定：墙与平面必须共享同一个规矩

`syTop` 是小数。第一行画在哪？本约定：

```
墙的第一行 = ceil(syTop)；与墙相接的上方平面带，末行 = ceil(syTop) − 1
墙的末行   = floor(syBot)；与墙相接的下方平面带，首行 = floor(syBot) + 1
```

两边共用同一个取整函数，交界处就既不重复也不遗漏。如果墙用 `floor(syTop)` 起笔、平面用 `ceil` 收边（或反过来），交界处要么留一像素缝、要么平面盖掉墙第一行。最折磨人的是它的**间歇性**：深度凑巧让 `syTop` 落在整数附近时才发作——玩家在房间里走两步，缝一闪一闪；把玩家摆到坐标整点上截图，一切正常。第 07 章的收边规则和验收工具会再遇到它。

## 这样做的代价 / 放弃了什么

- **贴图是逐列采样的位图，没有过滤。** 1 单位 = 1 texel 加上最近邻取整，远处的墙一个 texel 抖动一帧，闪烁是这套模型的固有属性（原版用米普贴图缓解地面，墙照闪不误）。
- **每列一次求交、每行一次反投影**，全是乘除。定点化时这里的精度最紧张（第 02 章），浮点实现则要注意：正反投影必须用**完全相同**的表达式，各写各的迟早在第 05 章的边界列之外再多造几种缝。
- **墙的深度是列常数。** 一堵斜对着你的墙，整列用同一个 `scale` 是透视投影在"垂直面"上的严格结论，但这也意味着任何非垂直的东西（斜坡、倾斜贴图墙）在这套模型里根本不存在——DOOM 的几何语言里没有它们，不是没实现。
- **pegging 表是约定不是推导。** 四种面、两个标志、rowoffset 与 textureoffset 的叠加顺序，任何一格记反都不会报错，只会在某个关卡的某面墙上看起来"不对"。把它们全部列成一张表、逐项对着地图验证，比背原版源码可靠。
