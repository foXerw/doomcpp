# 05 BSP 遍历与可见性

## 不做这件事会看到什么

假设你把地图里所有墙按存储顺序画到屏幕上：先画远处的墙，再画近处的墙，近处的没问题；但只要顺序反过来，远处的墙就会盖掉近处的墙——一堵 4 格厚的走廊变成只有最后一面墙可见，怪物被"贴"在墙皮上。你可以上 z-buffer，每个像素存一个深度；但原版 DOOM 没有。它用一个更便宜的办法：**让画的出现顺序本身就是深度顺序**。这一章讲这个办法怎么成立、成立到什么程度、以及在边界上它会以什么方式失效。

## 节点树是一棵分割树

地图在构建期被一棵 BSP 树预先切好（第 04 章讲过切分产物）。每个内部节点存一条分割线：起点 `(x, y)`、方向向量 `(dx, dy)`，以及两个孩子。约定：`(dx, dy)` 的**左手侧**（叉积 `dx·dy' − dy·dx' > 0` 的一侧，即法向 `(−dy, dx)` 指向的一侧）称为 front，`children[0]` 就是 front 子树；`children[1]` 是 back。叶子是一个 subsector（子扇区），在节点 lump 里用孩子编号的最高位（`0x8000`）标记：

```
struct node_t {
    mapUnits x, y; fixed32 dx, dy;
    uint32 children[2]        // 最高位置 1 => 低 15 位是 subsector 编号
}
```

## 遍历：近的孩子先画

```
function renderNode(idx):
    if idx 带叶子位: renderSubsector(idx & ~0x8000); return
    n     = nodes[idx]
    side  = 相机在 n 的哪一侧          // 0 = front, 1 = back
    renderNode(n.children[side])       // 近的孩子
    renderNode(n.children[side ^ 1])   // 远的孩子
```

`side` 的判定不需要真正的叉积符号，两次乘法比较就够了：

```
function pointOnSide(px, py, n):
    left  = n.dy * (px − n.x)
    right = n.dx * (py − n.y)
    return (right < left) ? back : front
```

为什么近的孩子一定更近？分割线把平面分成两个半平面，相机在 front 侧时，front 子树里的所有点都在分割线的这一侧，back 子树里的所有点都在那一侧。这条线本身是相机与 back 子树之间不可逾越的屏障：从相机射向任何 back 内容的光线必然穿过分割线所在的无限直线，也就是说必然先经过 front 一侧的空间。递归地把这个论证用在每个节点上，得到的全局性质是：

> **任何屏幕像素上，先被画到的几何体一定挡在后面被画到的几何体之前。绘制顺序 = 深度顺序。**

这就是不需要 z-buffer 的根本原因——不是"省内存的权宜"，而是遍历顺序提供的强保证：后画的东西永远是"更远的或同深度的"，直接覆盖即可。代价是：可见性判断全部发生在遍历当下，错过就无法补救。第 07、08 章里那些"缝""遮挡"问题，根源都在这里。

## 两块裁剪数组：唯一的可见性状态

"挡住"在 DOOM 里不是逐像素比较，而是每列两个整数：

```
ceilingClip[x]   // 顶部向下：已涂到的最后一行（初值 −1 = 一行未涂）
floorClip[x]     // 底部向上：已涂到的最低一行行号（初值 = 视图高，即"越界一格"表示未涂）
```

`ceilingClip[x] = 59` 的意思是"第 x 列的 0..59 行已经被不透明几何体封死"；`floorClip[x] = 120` 表示"120..视图底已经被封死"。两行之间只剩 `ceilingClip[x] + 1 .. floorClip[x] − 1` 是开放窗口。一堵墙画完后，只有**不透明**的部分才会推进钳位：

```
if 墙段不透明:
    ceilingClip[x] = max(ceilingClip[x], 墙底行)
    floorClip[x]   = min(floorClip[x],   墙顶行 − 1)
```

一个 seg 的可见列范围 `[x0, x1]` 里，如果**每一列**都满足 `ceilingClip[x] ≥ floorClip[x] − 1`（窗口宽度 ≤ 0），这个 seg 整段跳过——这就是"这堵墙在全视图里都被挡完"的判据，逐列生效，不需要任何显式的遮挡查询。

这个模型对**masked（中空）墙**特别关键：栅栏、铁窗这类 middle 贴图逐 texel 画，alpha=0 的 texel 跳过且**不更新两块钳位**。钳位不推进，意味着 BSP 序里后面那些更远的 seg 仍然"看得见"这几列——几何体从中空处透出来。可见性状态里根本没有"这个像素被栅栏占了"的概念，只有"这个像素被不透明体封了"，这是同一种设计的两面。

## 近平面裁剪，以及一处"故意不自洽"

相机背后的顶点投影后会翻到屏幕另一侧（深度为负，除法结果镜像）。所以画之前必须把落在 `depth ≤ near` 的端点裁到近平面上（`near` 取一个很小的正数即可）：

```
d0, r0 = 端点1 的相机坐标(前向深度, 横向);  d1, r1 = 端点2
if d0 ≤ near 且 d1 ≤ near: return        // 整段在身后
if d0 ≤ near: t = (near − d0)/(d1 − d0); d0 = near; r0 += (r1 − r0)·t
同样处理 d1
x0 = round(半宽 + focal·r0/d0);  x1 = round(半宽 + focal·r1/d1)   // 用裁后的
```

注意最后一行：屏幕列范围用**裁剪后的**端点算。但接下来逐列求纹理坐标时，射线与线段所在直线的交点参数必须用**原始端点**算：

```
for x in x0..x1:
    sx = (x − 半宽) / focal                        // 该列的视线方向（横向/前向）
    t  = (sx·d0原 − r0原) / ((r1原 − r0原) − sx·(d1原 − d0原))   // 用未裁剪的端点
    U  = seg起点偏移 + sidedef纹理偏移 + t · seg原长
```

第一次写到这里的人几乎都会"顺手改正"这个不一致——两边都用裁剪后的端点。结果是被裁掉一端的那几列，贴图整体错位：`t·seg原长` 之所以等于世界里的距离，是因为 `t` 是**相对原始顶点**的比例。裁剪后的"假想顶点"不是真实几何点，它到另一端的比例乘回原长，得到的是一个随相机位置漂移的伪距离——纹理原点跟着相机滑动，而且和共享这个顶点的相邻 seg 对不上（邻居的 `t` 从真实顶点起算），墙角两侧同一张贴图错开一截。反过来，列范围如果也用原始端点算，负深度的端点会把 `[x0, x1]` 甩到屏幕反面，整个 seg 被错误丢弃或错误覆盖。**列范围回答"哪些列可能有光碰到这条线"，用裁剪后端点；交点参数回答"这列的光打在线上的哪个真实位置"，用原始端点。** 两者职责不同，不一致恰恰是自洽。

## 边界列陷阱：正反投影在两端差一个 epsilon

上面的逐列循环里，`t` 对 `[x0, x1]` 中间的列必然落在 `[0,1]`——列范围就是从这条线段投影来的。但在**恰好 `x0` 和 `x1` 这两列**，正投影（乘完取整到列号）和逆投影（除回来解交点）是两次浮点运算，结果会差一个 epsilon：`t` 可能算出 `−0.0000002` 或 `1.0000003`。如果代码写的是严格的 `if (t < 0 || t > 1) continue;`，被丢弃的不只是这一列的墙——这个 seg 的**平面标记**（第 07 章的 visplane 收边）也一并跳过。相邻那堵墙在这一列把钳位推到了这里，而本该接上的平面带又没人标：结果是一条**一像素宽的黑缝，恰好出现在两堵墙相交的墙角**。它只在特定相机位置出现，玩家走动时一闪一闪，极难归因。

修复是把"越界即弃"改成"只在非边界列弃"：

```
if t < −ε 或 t > 1+ε:
    if x != x0 且 x != x1: continue     // 真正的越界：视线打在线段延长线上
    t = clamp(t, 0, 1)                  // 边界列：吸附到线段端点
```

**但 clamp 必须只限边界列。** 如果对每一列越界都 clamp：一条几乎平行于屏幕、纵向远离相机的线，其端点之外的列 `t` 会成段地小于 0；clamp 把整段列钉在 `t=0`，于是这个 seg 用端点处的深度和 U 在**并不属于它的列**上画墙、推进钳位、以错误的深度写遮挡——后面的真墙被这些假列挡掉，屏幕边缘一整条墙皮消失，比黑缝严重得多。`x0/x1` 之外的列本来就不该属于这个 seg，越界是真实信息；`x0/x1` 上的越界是浮点噪声，吸附才是对的。

## 这样做的代价 / 放弃了什么

- **依赖构建期数据。** 遍历顺序即深度顺序的前提是节点树正确切分了地图。没有 BSP 的地图画不了；运行时改动几何拓扑（比如可破坏的分割线）在这套框架里不成立——原版因此把 BSP 冻结在地图 lump 里。
- **一遍过，没有补救。** 错过了就是错过了。所有"事后修补"（边界列吸附、第 07 章的收边规则）都必须提前想好，因为没有第二遍。
- **透明与半透明在遍历里仍然是顺序艺术。** BSP 序保证的是不透明几何体的严格深度序；masked 墙靠"不写钳位"糊弄过去，多个 masked 墙互相之间的相对远近，只有遍历先后说了算。精灵更特殊，干脆被逐出遍历、收集起来单独排序（第 08 章）。
- **钳位是列粒度的。** "挡住"只有"整列上下封死"一种表达，表达不了"这块墙中间有个洞"——于是需要 visplane 补天、需要每像素深度补遮挡。这两件事分别是第 07、08 章的主题。
