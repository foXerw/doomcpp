# 16 验证方法论

这一章是这本书的承重墙。前面每一章回答"怎么做"，这一章回答"怎么知道你做对了"——在没有参考引擎、没有逐字节判据的世界里，这是同一个问题的另一半，而且是没人教你的那一半。

先讲一个真实事故。某个版本的发布二进制里，**WASD 四个键按下去人物纹丝不动**。同一时刻：整套单元测试全绿，离屏渲染的整帧截图完美，编译器零警告。根因是主路径上少调了一次三角函数表初始化——静态数组全零，移动代码读到 `fc = fs = 0`，推力乘出来是 0。为什么没有任何门报警：每个单元测试都在自己的 fixture 里调好了初始化；离屏渲染是静态帧，不需要移动。绿灯不是证据，绿灯只是**门够不着这件事**。本章的整个体系就是为这类 bug 建的：不是"多写测试"，而是让每一层门检查上一层门看不见的世界。

## 16.1 第一层：纯逻辑单元测试，以及它凭什么必须存在

地基决定上层：核心逻辑（doomcore）不链接 SDL。这首先是第 1 章的架构决定，但它的验证红利在这里兑现——碰撞、BSP 遍历、机关状态机、伤害管线全部可以在没有窗口、没有声卡、没有任何资产的进程里调用。单元测试因此有两个武器：

**合成地图 fixture。**两三个手工构造的扇区（sector）、几条线定义（linedef）、一张迷你区块图（blockmap），直接喂给碰撞代码。真实地图在这里帮倒忙：E1M1 里"某条线挡住了玩家"这种断言无法写，因为那个结论依赖整张图；而在一个 64×64 的单房间加一扇半开的门里，"在 z=96 处移动应该被挡、在开口高度应该通过"是封闭的几何事实。合成 fixture 换来的是**可判定的因果**——断言只可能因为被测代码错而失败。

**确定性。**固定随机种子、固定 tic 数，同一测试跑一万次同一个结果。这是后面所有 soak 类审计的前提。

但这一层有个由生俱来的盲区，而且是结构性的：**每个测试自己搭建世界**。测试夹具（fixture）越周到，"生产路径忘了搭建世界"就越不可见。第一层的满分恰恰是盲区的原因。

## 16.2 第二层：runtime smoke——跑真实的启动路径

第二层只干一件事：**无头地走一遍真实二进制的真实路径**（`--smoketest`，注册为 CTest 门 `runtime_smoke`），并且断言可观察的效应而不是返回值：

```text
加载 E1M1（真装载代码） → P_SetupLevel（真出生）
断言 玩家物件存在；新怪物/弹丸精灵全部从 IWAD 解出
掷油桶（与 G 键共享同一个 P_TossBarrel 函数）→ 跑 45 tic
断言 弧线升高、离开地面、重力翻转动量 z
持枪前进 20 tic → 断言 位置变了        # ← 三角表没初始化就会死在这条
右转 10 tic → 断言 角度变了
按住开火 40 tic，面前 96 单位一只桶 → 断言 桶掉血
R_RenderView 一帧 → 断言 非清屏像素 > 25%
任一失败 exit 1
```

把它和第一层区分开的不是"测试得更全"，而是**它不做任何 setup**——所有初始化都必须由被测的生产路径自己完成。这一层专门猎杀"缺 setup"这类 bug：负控验证过——把 `R_InitTables()` 注释掉，smoke 在"前进改变位置"这条上红。事故本身（16 章开头那次）之后，这一层被立为永久门而不是排障临时工具，并且规矩写进了每个阶段的验收：**任何动了初始化、输入、新子系统的阶段，必须让 smoke 跑过才算完**——后续阶段的 `--aittest`（AI 唤醒链）、`--campaigntest`（整条流程状态机）、`--soundtest`（音频在无设备下必须安全沉默）都是同一形状的复制品：真路径 + 可观察效应 + 退出码。

## 16.3 第三层纪律：负控——每个门必须被证明会红

以上两层合起来仍然不够，因为"门存在"不等于"门有效"。**每条门都要做一次演示：故意破坏被测功能，门必须红；恢复，门必须绿。**这件事要留在记录里（提交信息或门旁边的注释），因为它有一个邪恶的孪生问题：一道永远不会红的门，自身没有任何症状。本项目最贵的例子发生在资产审计门上——它的 critical 判定用字符串前缀比较自己的输出标记，比较长度错了一个字节，于是"永远没有 critical 失败"。门在 CI 里绿了不知多少天，最后一次独立评审打开代码才看见。教训要直说：**一道不能失败的门比没有门更糟，因为它在批量制造信心，而信心是免费的、不会再去查的东西。**负控的另一种形态是"改动前后对比"：给渲染器修一个遮挡 bug 时，同时记录"这一改，E1M1 起始帧变了 213 像素"——改动必须留下可测的痕迹，无痕的修复和无痕的 bug 无法区分。

## 16.4 第三层：对出厂内容做审计，而不是对 fixture

单元测试审"代码"，审计审**内容**：全部 36 张官方地图、玩家会到达的一切位置。三种形状，各抓到过单元测试原理上抓不到的东西。

**渲染覆盖审计（`--renderaudit`，门）。**每图取若干相机姿态、每姿态八个朝向，约九千六百余帧：清屏色用洋红哨兵，把 masked 贴图"设计上透明"的像素强制按不透明渲染（否则空洞统计和"本来就该看见的黑洞"混在一起），关掉安全网的接缝补色（审计要量裸真相），然后数**没有任何墙面和可视平面（visplane）覆盖到的像素**。容差 2——经验校准出来的"物理缝线"水平；超过半屏未绘制的姿态单独记为 suspect（地图里确实存在放不进玩家的密封袋间，它们不是覆盖洞，但混进统计会淹没真洞）。它抓到过：整条走廊的黑带（无贴图台阶面两侧平面带各让 1 像素，E2M2 等四张图，最多 23400 像素）、两墙相接处的 1 像素缝。这些 bug 每个单元测试都是绿的，因为它们全在"真实地图 + 真实姿态"的交界处。

**碰撞审计（`--clipaudit`，门 + 信息）。**核心思想一句话：**让引擎自己当自己的证人**。从出生点和散布网格的物件位置播种确定性漫游（一条随机游走只能覆盖约 2% 的扇区——它总卡在第一个墙角；从几十个散布点各走短程才盖得住真实地板），每走一步，拿碰撞代码本身复检漫游后的位置：这个位置 `P_CheckPosition` 自己放行吗？不放行而人却站在那里 = 引擎自相矛盾 = 穿墙。分层是这门的全部纪律：**跨阻挡线是门**（红灯）；**与 solid 物件重叠只是信息**——原版垂直规则允许"走下台阶正好落在一只怪物身上"，把它设成门就是在惩罚被实现的行为；被机关挤死也是信息（那是机关在执行职责）；**播种点本身站不进人就跳过并计数**——制图者确实会把物件放进墙里。它抓到过玩家 `mo->z` 从出生起不更新（高台上能直接走过怪物）、mover 目标未夹取导致的挤压穿顶。

**资产解析审计（`--assetaudit`，门）。**地图引用的每一个 flat、贴图、精灵名、物件编号都必须解析得到，白名单只留给出生点标记那几类编号。为什么必须审计而不是崩溃：失败的查找**不崩溃，它安静地什么都不画**。它抓到过一批 doomednum 缺失——黄/红钥匙两个编号的物件根本不生成，后果不是视觉 bug 而是若干关卡按设计无法通关。

## 16.5 姿态问题：相机的位置必须"可证明在真实空间里"

上面两个审计都依赖同一个前提：把玩家/相机放到一个合法的位置。这件事比听起来难，而且 BSP 会给一个诱人的假答案：**任意点都能被 `R_PointInSubsector` 解析出一个子扇区（subsector）**——虚空之外是最外层无界叶子，它也有编号、也有扇区。所以"BSP 有答案"不等于"在地图里面"；从虚空里渲染，画面空白不是 bug 而是几何事实，审计会把这种假洞报成整屏丢失。合法性的证明必须是联合的：BSP 解析出的扇区恰好是该点所属的那个、sector 垂直净高放得下 56 高的玩家、再用一条 +X 射线对该扇区边界边做奇偶计数确认点真在其中——最后这个奇偶测试用的是引擎自己的线几何，而不是手画的 bbox 启发式。姿态错了，审计红得再多也只说明审计坏了：**harness 的 bug 长得和引擎的 bug 一模一样，只能靠可证明的采样点把它们区分开。**

## 16.6 不靠人的视觉验证：眼睛和数字各查各的

图像最终还是要被看。自动化的是"看之前的路"：BMP 落盘 → 一个纯 stdlib 的小脚本转 PNG（无外网、无 PowerShell 执行策略，CI 可用）→ 人打开看。但**看之前先跑数字**：把每帧像素按颜色分桶计数。两种检查抓的是不相交的两个集合——

- **数字抓眼睛看不见的**：地平线一条 1 像素缝（中间行被 `yslope` 除零保护跳过），肉眼在动态游戏里永远看不到，直方图上却是"第 100 行黑色计数 ≠ 99/101 行"的铁证。`--gapscan` 的 `raw=` / `geometry=` 两个计数同样如此：差值就是 masked 贴图的合法透明区，肉眼分不出哪种黑。
- **眼睛抓数字看不见的**：贴图垂直镜像（V 坐标符号反了）——每个像素都有颜色、覆盖率满分，只有人知道灯管图案怎么会出现在墙底。Freedoom 状态条的 FRAGS 标签错位也是同一类：数字上"画了"，语义上"画错了地方"。

所以规矩是双轨：几何正确性交给数字门（覆盖率、缝、空洞），语义正确性（这是不是那面墙、这个 HUD 是不是给人看的）留给固定姿态的基线图 + 眼睛，每次渲染改动看一次。定位手段配齐：`--colprobe` 打印某一列被哪个段（seg）绘制、为什么跳过其余；`--gapscan-map` 复现审计报出的任何一组 (x, y, angle)——**审计输出必须自带复现命令**，红了的门如果没法五分钟定位，一周后就会被绕过。

## 16.7 诚实规则：当不了裁判的工具，就不许当门

最后一层不是技术，是纪律：**一个审计如果"可能错"，它就只能是信息，不能是门。**本书自己的反面教材是可达性模型：静态地按引擎的移动规则和 special 表走一遍扇区图，问"出口可达吗"——它报 15 张图 BLOCKED，而把这些图的前缘边列出来，**上面根本没有引擎不支持的 special**。是模型不懂（不会建模"乘电梯中途对齐平台再跳过去"、不会建模钥匙要清怪、不会建模开关隔着三个房间联动），不是引擎不能。另一个是贪心漫游求解器：只会"朝随机目标走再试别的"，36 张图只解出 7 张——离"关卡可完成"需要的规划差着一整个 AI。两者的归宿是永久 informational：退出码不接 CI，局限写死在工具自己的注释里（"把它的 gating 清单读成'special 待办'，仅此而已"）。

为什么这么较真？因为两种错的代价不对称。**常红的门会被忽略**——人对永久红灯的适应只需一个下午，之后它连真红灯也一起掩埋；**假绿的门会被信任**——它把"没查过"包装成"查过了"，直接污染使用它的人的判断。分类标准因此不是"这个检查重不重要"（可达性当然重要），而是"它报告的每一个红灯，我敢不敢让作者闭工去修"。不敢，就降级成信息，并把原因写在代码里而不是文档里——注释会被读到，文档不会。

## 16.8 让审计可复现：播种与记账

漫游和求解全部由固定种子驱动（xorshift，默认值硬编码在门定义里），于是"回归"这个词才有意义：同一命令、同一地图、同一二进制，结果逐数字相等。配套的记账习惯是**把数字写进提交信息**——修复平面带边界前"黑带 105~23400 像素"、修复后"geometry=0 × 全姿态"、遮挡改动"起始帧变 213 像素"、E1M1 起始帧接缝补色误伤"1372 像素糊掉"。下一个遇到数字变化的人，凭提交历史就能区分两件事：**"功能回归了"和"fixture/容差/资产换了"**。没有记账的审计数字只是一次性消耗品；有记账的审计数字是趋势线。

## 这样做的代价 / 放弃了什么

- 时间与预算：渲染审计九千多帧、碰撞审计深跑约两分钟——门必须分"CI 预算版"（限种子数、限姿态数）与"深跑版"（不设上限），两套参数同一份代码。
- 依赖资产：所有 runtime 门需要 IWAD，CMake 对缺失资产直接不注册这些测试——于是"CI 全绿"在不同机器上含义不同，读结果的人必须知道自己那台机器注册了几条门。
- 容差是标定出来的，不是推导的：`--tolerance 2` 这类数字背后是"逐个检查过报出的洞都是真洞"的一次性劳动，资产或渲染路径大改后要重标。
- 覆盖率仍是采样：审计证明"这些姿态没问题"，不证明"没有姿态有问题"。它把"玩家大概率会撞上的洞"变成红灯，把小概率角落留给真人。
- 最大的代价是维护心态：每个门都要负控、每条信息都要写局限、每次红灯都要能五分钟复现——这套纪律比任何单个工具贵，也正是它让工具值钱。

第 17 章会展示这套机器反过来咬人的样子：每一个"更忠实"的方案，都是先被这些门证明"它坏了别的东西"之后才被裁决的。
