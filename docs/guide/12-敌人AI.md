# 12 · 敌人 AI

> DOOM 的怪物没有寻路、没有行为树、没有效用函数。它们的"智能"几乎全部来自三样东西的复合：状态表（第 10 章）、一次便宜的视线测试、和一条写在伤害代码里的仇恨转移。本章讲这套最小配置，以及简化版与原版在手感上的真实差距在哪。

## 不做这件事会怎样

- 怪物永远背对玩家站着发呆——视线测试漏了，或者写了个"全图无墙可见"的版本。
- 躲到台阶后面，怪物照样穿过 16 单位高的矮墙精确命中你——视线只做了 2D，没查开口高度。
- 玩家开一枪，整个地图醒来——声音唤醒没有半径；或者反过来：火箭弹在怪物脑门上爆炸它毫无反应——噪声没接进唤醒。
- 两个怪物在门口互相顶死，谁也不让谁——thing 阻挡没有例外，追击没有绕行阶梯。
- 怪物永远不会自相残杀——伤害代码里少了一行本该在那里的赋值。

## AI 就是一个被 thinker 驱动的状态机

没有"AI 系统"这个独立 tick。怪物就是一个普通 mobj，它的待机状态行挂着 `A_Look`，追击状态行挂着 `A_Chase`，动作在**状态入口**派发（第 10 章的规则）。五组状态由 mobjinfo 的五列索引：

| 列 | 内容 | 迁移来源 |
|---|---|---|
| spawnstate | 循环播 A_Look | 出生 |
| seestate | 循环播 A_Chase | 看见/听见玩家 |
| meleestate / missilestate | 攻击动画，动作在入口打伤害 | A_Chase 按距离掷骰子 |
| painstate | 受踉跄 | 伤害 + painchance 骰子 |
| deathstate / xdeathstate | 死亡/爆碎 | 血量清零 |

`reactiontime` 是出生后的宽限（约 8 tic 内 A_Chase 直接返回）：怪物空降落地的一瞬间不能开火，否则玩家踏进房间就被预瞄爆头。唤醒分两条互不相交的路：** sight 类**——A_Look 每 tic 廉价环视；**noise 类**——枪声直接调用唤醒函数改写 target 并切状态，不经过 A_Look。

## 视线：便宜且正确

视线是怪物 AI 的全部感官，必须同时做到便宜和正确。正确性只有一条规则：

```text
P_CheckSight(观察者, 目标):
    从观察者眼睛（z + height×3/4）到目标画 2D 射线
    对每条与之严格相交的线：
        单侧线 → 挡住
        两侧线 → 求开口；射线在该交点处的高度 z 不在
                  [bottom, top] 内 → 挡住
    全部通过 → 可见
```

关键在"开口包含射线高度"：**矮台阶能藏住你**（眼睛高度低于 opening 上沿的墙——不对，是对方眼睛的高度落在开口之外；一块 16 单位高的台阶对站着的东西就是天花板），**窗户关不住视线**（两侧线、开口贯通，射线从中穿过）。低墙躲怪和隔着窗户被打这两件事，不是两个特例，是同一条规则的两个投影。

射线的实现可以逐步加钱：doomcpp 现在暴力遍历全部线（一两千条，每 tic 每怪一次，接受范围内）；原版用 blockmap 走射线（P_PathTracing），顺路还能查 thing——查"射线会不会先被打断"的 hitscan（第 13 章）和视线共用这套遍历，所以"看得见 ≈ 打得着"天然一致。

昂贵测试之前是两道免费闸门，顺序不可颠倒：

```text
if 距离 > 视距上限: 不查
if 不在视锥内(|Δ角| > 90°): 不查     # MF_AMBUSH 跳过这一条
if 2D射线被挡: 不查
→ 唤醒：target = 玩家，state = seestate，播放发现叫声
```

`MF_AMBUSH` 让伏击怪失去方向感：三百六十度全向唤醒，但只被玩家踩进其子扇区/射线直触激活。门后埋伏的手感就是这一位标志给的。

## 追击：无寻路的五步试探 + 两条活着的细节

```text
A_Chase:
    转向 target
    看得见 && 距离 < 64 && 有 meleestate → 进近战
    看得见 && 距离 < 1024 && 骰子命中  → 进远程
    否则移动：按 期望角, +45°, −45°, +90°, −90° 依次试一步，
              第一个通过 P_TryMove 的方向就迈出去
    全部失败 → P_UseLines()：朝前方伸手够得着的开关/门，用掉它
```

两个细节决定怪物是"活着"还是"抽搐"：

1. **够门。** 被墙挡住时试着开掉面前的门——怪物走的是和第 11 章完全同一个 use 通道。门后躲玩家的老玩法因此自动失效，而实现只是一行调用。
2. **方向记忆。** 原版 `P_NewChaseDir` 记住"这个方向刚试过、不通"，失败后换轴重试，几 tic 内必然脱离墙角；没有它，怪物在凹角里 45/−45 对称振荡到永远。这一位"记忆"字段很便宜，但它属于下面那笔更大的投资。

**更大投资的真实账单**：完整复刻原版移动需要——blockmap 的 thing 链表（怪物要"看见"别的怪物在哪，才能避让）、物件每次移动时从旧格摘除/挂入新格的维护、`trydir` 试探方向表、以及"不主动撞同类"的判定。这套东西牵动第 09/10/13/16 章的多个接口（渲染收集、存档、hitscan 都要跟着改）。**简化版放弃它，代价是可感知的**：走廊里怪物排成一列纵队、门口堆成一坨互相顶着（MF_SOLID 谁也不让谁）、永远不会包抄。DOOM 的恐怖感恰恰一半来自"被围住"——这是简化版最贵的一笔欠账，值不值得还，取决于你要的是能玩还是像。

## 内讧：一行赋值，涌现一个玩法

伤害函数里加一条：

```text
P_DamageMobj(受击者, 来源, ...):
    受击者.target = 来源          # 就这一行
    受击者.reactiontime = 0
```

而 A_Chase 本来就会走向 target、按 target 距离和视线选择攻击状态——"仇恨"不需要新系统，**复用追击通道即可**。涌现效果：油桶爆炸伤到三个怪，它们互相指认为凶手，整个房间自己打起来，玩家在门口看完一场免费烟火。这是数据结构选择（target 是通用的"我恨谁"，不区分阵营）的直接红利。原版还有一条 `MF_JUSTHIT` 优先级（"刚打我的"压过"原本追的"，让玩家能脱战后重新拉怪）；doomcpp 简化版没有它，症状是：怪物一旦开始内讧就至死方休，玩家走近也不回心转意。

## 三种攻击 = 状态表三种形状

| 形状 | 判定 | 状态表特征 |
|---|---|---|
| 近战（蜘蛛、粉丁） | 距离 ≤ 64 直接给伤害，不要求视线 | meleestate 挂 melee 动作，missilestate 为空 |
| hitscan（僵尸、射手） | 与视线**同一套**射线 + 散布抖动 + 计算 slope | 先 A_FaceTarget 再开火 |
| 抛射物（imp、caco、男爵） | 生成 thinker、按斜率给动量（第 10 章） | A_Chase 距离 < 64 优先近战，否则远程 |

"caco 悬火球、imp 跳脸近战混合"这类怪物性格，全部写在五列状态索引和 mobjinfo 数值里，动作函数库里没有"怪物类型 if"。

**painstate 与 painchance** 是一列纯调参数：受伤后 `骰子 < painchance` 才踉跄。僵尸 200/256（几乎必硬直）、男爵 50（经常无视）、粉红魔鬼被调成近战专精（missilestate 指向同一状态）。玩家资源管理的一半——"大枪打小怪会被打断，打 boss 要算硬直窗口"——就是这一列数字。

## boss 死亡的花招与计数纪律

`A_BossDeath` 的核心问题是"**它是最后一个同类吗**"：遍历活物件，找到同 info 且血量>0 的 → 是则无事发生，否则触发剧情（E2M8/E3M8 直接终关；E1M8/E4M8 把 tag-666 的地板降下去，露出口子）。它必须防"两只 boss 同时死"的竞态：后死者检查时先死者已不满足"活着"。

推广成纪律：**killcount / 结算百分比必须由杀死物件的那一段代码维护**（P_KillMobj 里 +1，按 MF_COUNTKILL）。结算时回头重新数世界是错的——被压碎机关杀死的、被 telefrag 清掉的、读出关后还挂在链表上的尸体，三种都会漏。

## 声音唤醒：潜行玩法的前提

开一枪（以及怪物的火球命中墙），调用：

```text
P_NoiseAlert(发声者):
    半径 1200 内、当前没有 target 的、能看见发声者的 counting 怪
    → target = 发声者，reactiontime = 0，切 seestate
```

没有它，"安静地各个击破"不存在——玩家的所有行动自由都建立在"枪声是位置广播"这一条上。原版还有更细的传播（传送不算噪声、枪声唤醒以玩家为中心而非声源）；半径 + 视线这两道闸门已足够生成正确的手感。注意"没有 target 才唤醒"：正在追你的怪物不需要第二次通知。

## 这样做的代价 / 放弃了什么

- **无寻路 + 无同类避让**：走廊排队、门口堆叠、不包抄。省下的是 blockmap-thing 链表这一整套维护（第 10 章的渲染方案因此也可以不建它）；还欠的手感债要诚实记账，不要误诊成碰撞 bug。
- **暴力全线的视线**：正确，但复杂度随关卡线数线性走；怪物数量上千或要做 P_PathTracing 复用时必须换成块遍历。
- **没有 MF_JUSTHIT**：内讧不可逆，玩家无法"劝架"回仇恨。这是行为差，不是 bug——文档写明白，防止未来被当成穿墙同类项"修好"。
- **攻击状态只按距离和固定骰子切**：怪物没有弹道预判、没有掩体意识、没有撤退。原版的"笨"是设计的一部分——DOOM 是走廊射击游戏，怪物精确得会毁掉它；本章所有简化都优先保护这一点：**怪要凶，但必须蠢得可信。**
